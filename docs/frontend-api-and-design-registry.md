## 1. Architecture & Frontend Design Decisions (PM & Lead Dev Log)

### 1.1 Reactive Phone Scaling & Responsive Layout System (`mobile/src/responsive/`)
To ensure the mobile application scales cleanly across small Android phones (`320dp–360dp`), standard phones (`375dp–411dp`), and large phones/foldables (`412dp–768dp+`) without text clipping or broken grids:

| Decision Area | Problem Identified | Architectural Decision & Implementation |
|---|---|---|
| **Reactive Window Metrics** | `scaling.ts` previously captured `Dimensions.get('window')` once at module load, never updating on screen rotation, split-screen, or foldable posture changes. | Upgraded [`useResponsive.ts`](../mobile/src/responsive/useResponsive.ts), [`breakpoints.ts`](../mobile/src/responsive/breakpoints.ts), and [`scaling.ts`](../mobile/src/responsive/scaling.ts) to compute live metrics from `useWindowDimensions()`. |
| **Phone Size Tiers** | Single `<768px = mobile` breakpoint could not distinguish a cramped 360dp viewport from a 430dp viewport. | Defined explicit phone tiers in `useResponsive()`: `isCompactPhone` (`width < 375`), `isStandardPhone` (`375 <= width < 412`), and `isLargePhone` (`width >= 412`). |
| **Adaptive Gutters & Card Padding** | Fixed `20px` outer padding + `16px` card padding left only `288px` inner width on 360dp phones. | `useResponsive()` provides adaptive `gutter` (`16dp` on compact phones, `20dp` on standard/large) and `cardPadding` (`14dp` vs `16dp`), wired directly into [`ProfileLayout`](../mobile/screens/profile/profile-layout.tsx) and screen containers. |
| **Clamped Typography & Control Scaling** | `displayHero` (`46px`) and `displayTitle` (`42px`) wrapped onto 3–4 lines or overflowed narrow cards (Podium, Match Scoreboard, Investment Projection) on 360dp screens; additionally, Android Fabric (`ReactTextView`) shrinks text with `adjustsFontSizeToFit` inside intrinsic-width flex rows to ~4px. | Added clamped `moderateScale(size, factor)` (`[0.88x, 1.12x]` relative to a `390dp` baseline), explicit `isCompactPhone` typography tier downshifts (`h1` vs `displayTitle` / `displayHero`), `numberOfLines={1}` ellipsis, and removed `adjustsFontSizeToFit` across `Button`, `SegmentedTabs`, `SeverityPill`, `StatTile`, and `LeaderboardParts` so Android Fabric renders crisp, full-size labels. |
| **Multi-Column Grid Reflow** | Fixed `minWidth`/`flexBasis` in pixel units caused orphan wrapping on 360dp phones (e.g., 4 `StatTile`s in `Profile` wrapping 3+1; 4 `SeverityPill`s in `Feedback` wrapping 3+1). | Standardized 2-column grids on `flexBasis: '47%'` (`Profile` compact stats, `Points` legend & opportunities, `ChallengeDetail` metadata, `OptionTile`, `InterestTile`) and `flex: 1` single-row distribution for `SeverityPill`. Added `gridColumns(minTileWidth, gap)` helper to `useResponsive()`. |
| **Tournament Bracket Viewport Scaling** | Fixed `208px` bracket columns left awkward partial peeks on compact screens. | Scaled bracket column width dynamically via `Math.round(Math.max(188, Math.min(240, width * 0.56)))` with single-line ellipsis guards on participant names. |

### 1.2 Phase 0 Shared Component Decisions (`mobile/src/forms/` & `mobile/src/components/`)
- **`Field` (`TextInput`, `TextArea`, `Select`)**:
  - Unified field surface token (`colors.surface`) across [`TextInput.tsx`](../mobile/src/forms/TextInput.tsx) and [`TextArea.tsx`](../mobile/src/forms/TextArea.tsx).
  - Added `showCharCount?: boolean` to `TextInput` to render `${value.length}/${maxLength}` alongside helper/error text, matching `v2/Field` in Figma.
  - Exported `Field` alias from [`src/forms/index.ts`](../mobile/src/forms/index.ts).
  - Replaced hardcoded modal backdrop `'rgba(0, 0, 0, 0.65)'` in [`Select.tsx`](../mobile/src/forms/Select.tsx) with `colors.overlay` and migrated `SafeAreaView` to `react-native-safe-area-context`.
- **`SegmentedControl` (`SegmentedTabs`)**:
  - Exported both `SegmentedTabs` and `SegmentedControl` from [`src/components/index.ts`](../mobile/src/components/index.ts) with single-line auto-fitting labels (`numberOfLines={1}`, `adjustsFontSizeToFit`).
- **`StatTile`, `OptionTile`, `SeverityPill`, `InterestTile`, `ListRow`**:
  - [`StatTile.tsx`](../mobile/src/components/StatTile.tsx) uses `colors.surfaceInner` (matching `.stat` in Figma v2) and auto-scales values so timestamps and large numbers never clip.
  - [`OptionTile.tsx`](../mobile/src/components/OptionTile.tsx) and [`SeverityPill.tsx`](../mobile/src/components/SeverityPill.tsx) include selection haptics (`expo-haptics`), disabled states, and responsive flex sizing.
  - [`InterestTile.tsx`](../mobile/src/components/InterestTile.tsx) supports both explicit pixel width (used in onboarding grid) and responsive flex-basis sizing (used in `EditProfile`).

### 1.3 State, Reliability & Backend Integration Decisions
1. **Durable Idempotency on Point Investments (`D3`)**:
   - [`InvestmentRepository.ts`](../mobile/src/repositories/InvestmentRepository.ts) persists a generated UUID v4 `request_id` per `{eventRef, amount}` in `expo-secure-store` before calling `POST /leaderboards/events/:ref/invest`. It clears the key only on a definitive response (`2xx` or client `4xx` other than `408`/`409 request_in_flight`/`429`), preventing duplicate point debits across flaky campus Wi-Fi retries.
2. **Backend Enhancements Added for Mobile v2 (`media-service` & `user-service`)**:
   - **Viewer Like State (`H3`/`H4`)**: Updated [`media.service.ts`](../Backend/apps/media-service/src/media/media.service.ts) so `GET /media` and `GET /media/:id` return `liked_by_me: boolean` for the authenticated viewer.
   - **Uploader Pending Media (`H3`)**: Added `mine=true` query support (`GET /media?mine=true&status=pending`) in [`media.schemas.ts`](../Backend/apps/media-service/src/media/media.schemas.ts) and [`media.service.ts`](../Backend/apps/media-service/src/media/media.service.ts) so members can see their own pending uploads on the Media screen (with preview via `GET /media/:id/file`) without exposing other users' unmoderated uploads.
   - **Avatar Removal (`F7`)**: Added `DELETE /users/me/avatar` in [`user.routes.ts`](../Backend/apps/user-service/src/users/user.routes.ts) and [`user.controller.ts`](../Backend/apps/user-service/src/users/user.controller.ts) to clear `profile.avatar_url`, remove the stored file under `/uploads/avatars/`, and publish `UserProfileUpdated`.
3. **Strava Proof & OAuth Deep Linking (`E4`/`E6`/`E7`)**:
   -Configured custom URL scheme `bgsc://settings/integrations` in [`app.json`](../mobile/app.json) and [`layout.tsx`](../mobile/screens/drawer/layout.tsx) to intercept Strava OAuth callbacks and complete `POST /strava/link`.
   - On `ChallengeDetail` (`E4`), added a Strava activity quick-picker (`GET /strava/activities?limit=5`) so connected athletes can attach a synced Strava activity URL as challenge proof in one tap.

## 5. Web Admin (`web/`) Frontend Design Decisions & Complete API Registry

**Scope:** Web Admin Console (`web/`), React 19 + Vite + Tailwind CSS + Zustand + React Router v7.

### 5.1 Architecture & Design Decisions
1. **Ponytail Minimalist Admin Aesthetic**:
   - High-contrast, monochromatic design system with stark black borders (`border-black`), crisp white cards, bold monospace numerals, and subtle gray accents (`bg-gray-50`, `border-gray-200`).
   - Zero unnecessary external UI frameworks (no heavy component libraries); built entirely with native React hooks, Tailwind utility classes, and `lucide-react` icons.
2. **Resilient Network Client with Transparent Auth Refresh (`web/src/services/apiClient.ts`)**:
   - Points directly to API Gateway (`http://localhost:3000` or `VITE_API_URL`) with automatic `{ success, data }` unboxing.
   - On HTTP `401 Unauthorized` responses from any non-auth endpoint, `apiClient` automatically calls `POST /auth/refresh` with the stored `refresh_token`, saves the new token pair, and replays the original request once transparently without disrupting the administrator's workflow.
3. **Dual-Mode Operation (Mock vs Live Gateway)**:
   - Every service (`userService`, `eventService`, `registrationService`, `announcementService`, `bracketService`, `auctionService`, `mediaService`, `leaderboardService`, `feedbackService`, `challengeService`, `hallOfFameService`) cleanly checks `VITE_USE_MOCK === 'true'`.
   - In live mode, all payloads and response mappings strictly conform to the backend microservice Zod schemas and Mongoose models (`_id` vs `id` normalization, snake_case payloads, ISO 8601 datetimes).
4. **Events Part 2 — Dynamic Registration Form Builder & Lifecycle Management**:
   - **Form Schema Adaptation**: The backend registration service (`/forms`) requires `fields[].options` as `{ value: string; label: string }[]` and an explicit integer `order`. `registrationService.ts` handles seamless bi-directional translation from the admin UI's intuitive comma-separated format into the backend Zod contract.
   - **Formless Draft Invariant**: In accordance with the backend model invariant (`no registration form is only valid for a non-teamed, uncapped 'DE' event`), new events without an attached form default to `status: 'draft'`. Once a form is authored and published via the Form Builder tab, the event is linked (`registration.form_id`) and transitioned to `upcoming`.
5. **Challenges Admin & Review Queue (`web/src/pages/Challenges.tsx`)**:
   - Supports catalog management across `sports`, `esports`, `dev`, and `general` domains.
   - Physical challenges automatically require and capture `location: { name }`.
   - Includes a dedicated Review Queue modal allowing coordinators and core admins to inspect submitted proofs (`text`, `url`) and approve/reject payouts.
6. **Hall of Fame Inductions (`web/src/pages/HallOfFame.tsx`)**:
   - Supports honoring individual users (`type: 'user'`, populated with real user UUIDs from `userService.getUsers()`) or teams (`type: 'team'`).
   - Enables one-click Featured toggling (`PATCH /hall-of-fame/:id`) and deletion.
7. **Auction Console Live Director Integration (`web/src/pages/Auction.tsx`)**:
   - Includes an active event selector dropdown so administrators can switch between auction tournaments.
   - Normalizes lot identifiers (`_id`, `lot_id`, `id`) and provides controls to **Start Auction** (`POST /auction/events/:ref/start`), **Pause / Resume**, **Advance Lot / Hammer**, **Close Auction**, and update configuration parameters.
