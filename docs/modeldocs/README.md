## Conventions used in every doc

| Convention | Decision |
|---|---|
| Database | NoSQL document store. Written in MongoDB terms (collections, `_id`, indexes). BE-1 finalizes vendor today; nothing here depends on Mongo-only features except TTL indexes and `$inc`, both of which Firestore/DynamoDB have equivalents for. |
| IDs | `_id: string` — UUID v4 generated by the service. Not ObjectId, so IDs are portable across services and safe to put in JWTs, URLs, and domain-event payloads. |
| Cross-service references | ID strings only. **No joins across services.** Where the UI needs a name next to an ID, we store a small **snapshot** (`{ id, display_name, avatar_url }`) and accept staleness. |
| Timestamps | BSON Date, UTC. Field names end in `_at`. Every doc has `created_at`, `updated_at`. |
| Enums | lowercase snake_case strings. |
| Soft delete | `deleted_at: Date | null` where deletion must be reversible. Otherwise hard delete. |
| Ownership | Each collection is owned by exactly one service (listed at top of each doc). Only the owner writes it. |
| Events | Every state change emits a domain event from Spec §8.1. Listed per doc. MVP event bus = in-process emitter; Kafka later (see `docs/ARCHITECTURE_REVIEW_MEETING.md` §1). |

## MVP scope filter applied

From `MVP_Timeline_Plan_Updated.md` "MVP Scope Summary":

- **In:** events (incl. auction), registration (common), points, leaderboard, challenges, announcements.
- **Out:** sponsors, social feed, friends, store, unions. Sponsor hooks appear as **placeholders only** (`events.points_pool.sponsor_bonus`, `point_transactions.source: 'sponsor'`) so the schema does not need a migration when sponsors return (see `ARCHITECTURE_REVIEW_MEETING.md` §5).
- Tournament brackets / `matches` are Week 4 and **not designed here**; the `events` doc reserves a `bracket` slot.

## Plan gaps found while designing

- **Team model has no owner in the plan.** Spec §4.1 defines `Team` as its own entity and §5.15.4 auction (Week 3) cannot work without rosters and purses, but `MVP_Timeline_Plan_Updated.md` assigns no team task to anyone. Designed here as `team-model.md`, owned by Registration Service, generalized to events + challenges (Spec §5.7). Decision: Sep 5, 2026.
